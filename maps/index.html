How Cuvera's wine-region maps are made

Last updated: 4 November 2026

The Explore lessons in Cuvera include six simplified maps: Bordeaux, Napa Valley, Rioja, Burgundy, Chablis and the Barossa Valley. Each map is a picture drawn from open geographic data, with the place names added by the app. The maps are simplified for learning. They are not official or survey maps, and they do not imply any endorsement by the data producers.

This page describes the data and the method, as the Open Database License (section 4.6) asks of maps made from OpenStreetMap data. Cuvera does not publish the intermediate data.

Data sources

  • Coastlines, rivers, river areas, towns and peaks (Bordeaux, Napa Valley, Rioja, Burgundy, Barossa Valley): © OpenStreetMap contributors, available under the Open Database License (ODbL).
  • Wine appellation areas (Burgundy, Chablis): INAO, Délimitation parcellaire des AOC viticoles, update of 2 November 2026, Licence Ouverte 1.0.
  • The Serein river (Chablis): IGN, BD TOPO® (hydrographic sections of the Serein, last updated 21 August 2025), Licence Ouverte 2.0.
  • Barossa Valley and Eden Valley boundaries: Geographical Indications of Australia, © Wine Australia (2022 v1 edition, since superseded), CC BY 4.0, simplified by Cuvera.
  • American Viticultural Areas (Napa Valley, used only to check label placement, not drawn): UC Davis Library AVA project, CC0.

Method

  1. Download each region's data with the queries in fetch_<region>.sh: OpenStreetMap through the Overpass API; the national INAO shapefile from data.gouv.fr (fetch_inao.sh); the IGN hydrography through the Géoplateforme WFS service; the Wine Australia regions from their open-data release.
  2. Extract appellation areas from the INAO shapefile (inao_extract.py): filter by appellation and commune, convert from Lambert-93 to latitude and longitude, simplify (Douglas–Peucker, 8 to 60 m).
  3. Reduce the IGN river network to a single line (ign_mainline.py): the shortest path through the main flowing network.
  4. Project every layer onto the map's own grid, 340 units wide, with the linear formula in <region>.config.json: x = x0 + (lon − lon0) · kx, y = y0 + (lat0 − lat) · ky (build_map.py).
  5. Generalise: chain each river's ways into continuous lines, simplify them (Douglas–Peucker, 0.25 to 1.2 grid units) and smooth them (two Chaikin passes); keep only the water areas of the main rivers; drop short side channels; merge appellation parcels into zones (dilate then erode by 3 to 4 grid units, soft edge); mask the few features that are too small to read, as listed in each configuration.
  6. Render the base image at four times the grid (rendermap.swift, macOS CoreGraphics): the sea is flood-filled from seed points bounded by the coastline; rivers and appellation tints are drawn in Cuvera's palette.

The configuration files list every parameter, filter, seed point and mask used for each map. Running the steps above with them reproduces the base images.

How to run it

Requirements: macOS with the Xcode command-line tools (for swiftc), Python 3, curl and unzip. Put the files below in one folder, then for each region (Bordeaux shown):

sh fetch_bordeaux.sh data
python3 build_map.py bordeaux.config.json data scene.json
swiftc -O rendermap.swift -o rendermap && ./rendermap scene.json bordeaux.png

With the data as published on 4 November 2026, these steps reproduce Cuvera's base images exactly. OpenStreetMap is edited continuously, so later downloads can differ slightly; the Napa Valley configuration also names three OpenStreetMap water areas by their identifiers.
